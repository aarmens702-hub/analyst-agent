# Wave 1.5: what the fixes broke

2026-09-07. **Status: triage of a diff-scoped review, for owner review.**
32 findings, every one confirmed by an adversarial verifier told to refute by
default (7 sub-claims were refuted and removed). Scope: only the ~1800 source
lines that landed after `f9ddf34`, in the four remediation packets P0 security,
P2 verification, autonomy, and wave 1 scorer.

**These are not more of the original 56.** Those are year-old debt, still open,
still triaged in `2026-09-06-review-triage-and-fix-plan.md`. These are
regressions we created in the last two days. That is why they jump the queue
ahead of wave 2.

**Over-refusal plus over-claim is 19 of 32.** P2 taught the fixers to refuse
rather than mangle, which was right, and the risk inverted: the live failure is
now declining input crivo should repair. It hides as a lower number that looks
like rigour, because a survival rate cannot distinguish "correctly declined to
guess" from "broke and stopped fixing things it used to fix well."

The second half of the pattern is worse than the first. Several fixes wrote a
docstring describing a hole as closed while closing only part of it, so the
documentation now asserts a guarantee the code does not provide. A reader
checking the code against its comment would conclude the bug was fixed.

**One of those over-claims is mine.** The wave 1 commit message (`9f1d996`)
states the retracted recall "is not constructible" from the published counts.
It is constructible exactly, by the subtraction the docstring itself invites.
That claim was asserted as verified fact and was wrong.

## R0. Safety inversions and mutual exclusions

Fix first. Each is a guarantee that was true before these packets and is not
true now.

1. **`loop.py:1489` a rejected plan now applies every AUTO fix unattended.**
   The autonomy packet's seeded `autonomy-auto` policy outlives the PLAN gate,
   so a person who rejects the plan gets the AUTO steps applied silently, where
   the pre-packet state stopped them. Rejection was inverted into approval.
   Fix: treat reject at the PLAN gate as `proceed=False`, or suspend the seeded
   policy for findings the rejected plan covered, and have `policy.evaluate`
   prefer a plan-armed record over the seeded one so the transcript names the
   approval that actually applied.
2. **`mcp_server.py:172` the two P0 security fixes cancel each other.**
   `CRIVO_MCP_SANDBOX=docker` and `CRIVO_MCP_ROOT` are mutually exclusive:
   `_make_session` passes `docker` but never `data_dir`, so every path that
   clears the new root check then dies in `Session._kernel_path`. Sandboxing
   and path confinement cannot both be on.
   Fix: pass `data_dir=str(_root())` so the mount and the root are one
   directory, or refuse at startup and name both in the message.
3. **`loop.py:604` an unapproved plan writes a clean bill of health.**
   The report reads "0 fixed, 0 skipped, 0 failed, 0 not attempted, 0 flagged"
   over a dirty frame, which is the exact shape the report-only branch ten
   lines above was added to prevent.

## R1. Over-refusal, actively costing repairs today

These depress the 0.731 and 0.673 we just published.

4. **`detect.py:518` a uniform single-currency column regresses AUTO to
   HUMAN.** `_units_worn` unions the leading `$` with the `usd` suffix drawn
   from the same value, so `'$1,200.00 USD'` reads as two units. The emitted
   evidence then states a falsehood about the data. Also hits `'20°C'` beside
   `'21° C'`, and `'12 oz'` beside `'16 fl oz'`. The packet's own tests declare
   that refusing a single-unit column "would be over-refusal, not caution", so
   this fails its own stated bar.
   Fix: a value wearing both a symbol and its own ISO code wears one unit.
5. **`detect.py:475` `UNIT_LETTERS` reads only the first letter run**, so
   `km` and `km/h`, `mg` and `mg/dL` collapse to one token and a genuinely
   mixed column stays AUTO. The mirror of finding 4: too coarse in the other
   direction.
6. **`files.py:135` the bomb guard refuses an ordinary `.csv.xz` export.**
   The 200:1 ratio was calibrated on gzip; bz2 and xz reach it on honest
   boilerplate-heavy CSV. A free keyless diagnose now fails on a real file.
   Fix: per-format ratios, or drop the ratio for bz2/xz and keep only the
   absolute expanded-bytes ceiling.
7. **`repl.py:223` five unrecognized answers abandon the run and lose work.**
   A bare Enter counts as one. The `EOFError` escapes the session and the clean
   generator is dropped mid-run: no report, no lineage, no parquet, while the
   fixes already applied stay applied. The complaint line also offers "the
   words themselves" while rendering reject as `[j]eject`.
8. **`verify.py:466` hashing the index fails a legitimate reorder.** Any fix
   that reorders rows and resets the index trips the untouched-column guard.
9. **`autoclean.py:111`** the scale-suffix gate reads only the first letter
   run, refusing a unit that merely begins with m, k or b.
10. **`autoclean.py:179`** `_ORDER_SUPPORT`'s 20% floor refuses slash-family
    date columns where exactly one slot order can parse at all, and reports it
    as a verification failure.
11. **`autoclean.py:361`** `_repeats_header` matches case-folded and
    whitespace-collapsed while `_d18` counts header rows verbatim, so a padded
    header repair is refused over a row the finding never reported.
12. **`score_fixes.py:87`** the float branch rounds to 15 significant digits,
    so a cleaned parquet float that is the exact shortest round-trip of a
    16-digit truth literal scores as a wrong repair.
13. **`mcp_server.py:75`** `_client_path` resolves a relative client path
    against the process cwd rather than the root, so when the cwd sits outside
    the root every relative path is refused.

## R2. Silent corruption and false verification

14. **`autoclean.py:272` a missing target is recorded as a verified fix.**
    The refusal arm also fires when the target name is absent, and the loop
    records the untouched frame as a verified d19, delivering informationless
    columns marked "fixed". The pre-P2 code had the same silent no-op; what P2
    added was a docstring naming this exact failure while guarding only the
    duplicate-name arm.
    Fix: refuse only when count > 1; when count == 0 raise, so the fixer-error
    and revert paths fire instead of a silent verified no-op.
15. **`autoclean.py:75` `SCALE_SUFFIXES` misses `MM` and `T`**, the finance
    spellings for millions and trillions, so `'1.5MM'` becomes `1.5` and is
    recorded verified. A million-fold error, silently. Note the genuine
    tension: `mm` is also millimetres, so where a token is two things the
    refusal is the safe reading, because a wrong magnitude is silent and a
    refusal is not.
16. **`detect.py:2243` a verified rename permanently blocks later
    verification.** The new missing-column refusal fires on a target that a
    different disease's already-verified fix renamed, so a d18 header repair
    blocks d22, d23 and d26 on the same column.
17. **`detect.py:2289` a partial d18 repair is recorded verified** when the
    repair introduces a new damaged name.
18. **`loop.py:1056` a human rejection retires a proven skill.** The new
    family replay gate feeds `reject` into the skill ledger as a verification
    failure, so two rejections retire a working mapping skill and record a
    false reason.

## Suggested order

R0 first, as one packet: they are inverted guarantees, and two of them undo
security or approval semantics we shipped this week. Then R1, because every
wrongly refused input is a repair lost and the published numbers are paying for
it now. Then R2. R3 folds into whichever packet touches its file, since a
correct fix usually makes the sentence true; the ones that survive get their
words corrected rather than their code.

## What this says about the process

The adversarial pass inside each packet asked only "did this fix work". It
never asked "did this fix break something else", and it never saw the other
three packets. Every cross-packet finding here was invisible to it by
construction. A diff-scoped review after a run of packets should be standard,
not an afterthought, and the per-packet attacker should be told that
over-refusal counts as a failure.
